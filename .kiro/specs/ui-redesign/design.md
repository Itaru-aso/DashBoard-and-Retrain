# UIリデザイン設計書 — 藍染テキスタイル

- 状態: 承認済み（2026-07-31 ユーザー承認）
- スコープ: フロントエンド全6ページ＋共通シェルの視覚デザイン一新とページ内レイアウト再構成
- 非スコープ: API・バックエンド・ルーティング・ビジネスロジック・hooks の変更（一切行わない）

## 1. 背景と目的

現行UI（ダーク＋グラスモーフィズム、シアン/パープルのアクセント）に対し、以下の不満が挙げられた。

1. 見た目のトーンを変えたい
2. 情報設計・レイアウトが古い（ダッシュボードとしての構成が定石に沿っていない）
3. 細部の洗練度が足りない
4. ページ間の統一感がない

利用者は工場の検査運用担当者。日常的な KPI 監視・タスク処理に使う業務アプリとして、
長時間見ても疲れず、状態（正常/注意/逸脱）が一目で判別できるデザインへ一新する。

## 2. 決定事項（ADR）

### 2.1 デザイン方向: E「藍染テキスタイル」を採用

ジッパー＝繊維・縫製の世界に根ざしたトーン。藍染の深い藍を大きな面（ヘッダ・サイドバー）に、
本文は生成り（未晒しの布）の温かな地。署名モチーフは「縫い目」の破線1箇所のみ。

**検討した代替案（モックアップ比較の上で却下）:**

| 案 | 概要 | 却下理由 |
|---|---|---|
| A. インディゴ・プレシジョン | ライトSaaS・IBM Plex・アンドンレール | 一次候補だったが、E のほうが題材との結び付きと独自性が強い |
| B. ソフト・ニュートラル | ライトSaaS・影付き白カード | 汎用SaaS感が強く独自性に欠ける |
| C. コンソール・グリッド | 濃紺ヘッダ×高密度メトリクス盤 | 密度優先で温かみに欠ける |
| D. グラファイト計器盤 | フラットなダーク計器風 | ダーク継続はトーン変更の意図に反する |
| F. 製図ブループリント | 方眼＋図枠＋製図インク | 硬質すぎ、日常業務の道具としては疲れる |

モックアップは `.superpowers/brainstorm/`（git管理外）に保存。

### 2.2 実装基盤: CSS Modules 継続＋トークン全面再設計

新規ランタイム依存なし。Tailwind / UIライブラリ導入は却下
（全面書き直しコスト、既製感が「独自性のあるデザイン」と相反するため）。

### 2.3 チャート配色: アクセシビリティ検証済みの3色

dataviz バリデータ（OKLab ΔE・CVDシミュレーション・コントラスト）で
生成り地 `#fdfcf8` に対し全チェック PASS を確認済み（2026-07-31）。

- 系列1（藍）`#3568ad` ／ 系列2（辛子）`#a87400` ／ 閾値（赤）`#b3402e`
- 制約: **辛子と赤を同一チャートに載せない**（この2色のペアのみ通常視で判別困難なため。
  実際の隣接は「藍×辛子」「藍×赤」のみで問題なし）
- ブランドの深藍 `#22406b` は明度・彩度不足でチャート系列には使えない（UI面専用）

### 2.4 フォント: Zen Kaku Gothic New 自前ホスト（承認済み）

- 和文: **Zen Kaku Gothic New**（400/500/700）。woff2 サブセットを `frontend/public/fonts/`
  に追加し `@font-face` で配信（既存 JetBrains Mono と同方式）。工場LANで CDN に依存しない。
  ライセンス SIL OFL。追加資産は数百KB〜1MB程度（ユーザー承認済み 2026-07-31）
- 数値（KPI大数字・テーブル・ID・ログ）: **JetBrains Mono 継続**（桁揃え保証・既存資産）
- フォールバック: `"Zen Kaku Gothic New", system-ui, "Yu Gothic UI", "Meiryo", sans-serif`

廃止するトークン（`--color-accent-cyan` / `--color-accent-purple` / `--color-panel-*` 等）は
参照箇所を新トークンへ置換する。

## 4. 共通UI部品（`components/ui/` 新設）

統一感の解消の本体。全ページはこれらの組み合わせで構成し、ページ固有CSSを最小化する。

| 部品 | 責務 |
|---|---|
| `Panel` | カード面。タイトル＋右端補助表示のヘッダ行を持てる |
| `PageHeader` | ページタイトル＋説明＋右端アクション（ボタン等） |
| `StatTile` | KPIタイル: ラベル＋状態チップ＋大数字＋補足（閾値まで残り等）＋スパークライン（任意） |
| `StatusChip` | 正常/注意/逸脱ほか汎用状態チップ（ok/warn/bad/neutral の4変種） |
| `Button` | primary（藍地白字）/ secondary（白地藍字・藍縁）/ danger（赤系） |
| `SegmentedControl` | 期間切替・状態タブ（単一選択） |
| `DataTable` 用スタイル | 等幅数字・右揃え数値列・行罫線 `--color-border-subtle`・ヘッダ帯 |
| `EmptyState` | 空状態の案内（何が無いか＋次の行動） |

実装は既存の関数コンポーネント＋CSS Modules 規約に従う（TypeScript strict・named export）。

## 6. ページ別レイアウト再構成（ナビ構造・機能・APIは不変）

共通パターン: `PageHeader` → フィルタ/アクション行 → コンテンツ（Panel群）。

### 6.1 ダッシュボード（承認済みモックアップ準拠）
1. PageHeader（タイトル＋「検査KPIの日次推移と閾値の逸脱状況」＋最終集計時刻）
2. フィルタ行: 期間 SegmentedControl（7日/30日/90日）＋号機・色番・サイズのセレクト
3. KPI 4タイル（StatTile）: 検査数・NG率・虚報率・見逃し率。
   状態チップ＋「閾値まで残り○pt」＋スパークライン。値は既存APIレスポンスから導出
   （日次系列と閾値は既に取得済みのデータ。新規APIは作らない）。
   スパークラインは**全タイル藍 `--chart-series-1`**・閾値は赤破線で統一
   （モックアップでは見逃し率のみ辛子だったが、§2.3 の「辛子と赤を同一チャートに
   載せない」制約に抵触するため藍に変更。タイルの識別はラベルが担う）
4. チャート3面: 検査数（棒）／NG率（線＋赤破線閾値）を2カラム、
   虚報率・見逃し率（藍・辛子の2系列＋各系列と同色の破線閾値）を全幅
5. 日次明細テーブル（DataTable様式・状態ドット）

> **実装時の変更（タスク5）**:
> - 期間 SegmentedControl（7日/30日/90日）は既存の開始日/終了日入力を**置き換えず**、
>   それらへの追加のクイック設定として実装した。任意の期間指定（既存操作フロー）を
>   維持するため（design.md §8「既存の操作フロー...を変更しない」・R7.4）。
> - 号機・色番・サイズは既存どおり自由入力のまま維持した（セレクトへの変更は見送り）。
>   色番/サイズの選択肢一覧を返す既存APIが無く、新設すると R7.2（新規APIを増やさない）
>   に抵触するため。号機は既存どおり選択肢を持つセレクト（`<select multiple>`）のまま。
> - KPIタイルの「状態チップ」は正常/逸脱の2値（remaining pt の符号）で実装した。
>   「注意」band の閾値がどの基準（比率・絶対pt）で決まるかの仕様が無いため、
>   独自の数値を発明しないための簡略化（3値化は基準が定まった時点で追随可能）。

### 6.2 タスク
状態 SegmentedControl（未着手/対応中/完了）→ テーブル（状態チップ・行アクション）。
状態遷移・コメント追記の操作は現行機能のまま、様式のみ共通部品化。

> **実装時の変更（タスク6）**:
> - SegmentedControl に「すべて」を追加した（§6.2 は未着手/対応中/完了の3値のみ記載）。
>   フィルタ解除の操作（既存の `<select>` は空値選択肢を持っていた）を維持するため
>   （§6.1 の期間クイック設定と同様、既存操作フローを削らない方針・R7.4）。
> - 状態→StatusChip variant の対応（OPEN=neutral・IN_PROGRESS=warn・DONE=ok）は
>   §6.2 に定義がないため実装時に決定。未着手=中立・対応中=注意・完了=正常という
>   直感的な対応とした。

### 6.3 閾値
PageHeader 右端に「閾値を登録」（primary）→ 一覧テーブル（有効/無効チップ・無効化アクション）。

> **実装時の変更（タスク7）**:
> - 登録フォームは既存どおり常時表示のPanelのまま維持した。「閾値を登録」primary Button は
>   モーダル/トグル開閉ではなく、フォームへの `scrollIntoView` によるショートカットとして実装
>   （既存の即時表示フロー・既存テストの入力可能性を変更しないため。§6.1/§6.2 と同じ方針）。
> - 有効/無効 StatusChip は既存フィールド `valid_to`（null なら有効・値があれば無効）から導出。
>   新規APIは追加していない。

### 6.4 色マスター
検索行＋「CSV取り込み」→ テーブル（色見本スウォッチ、ライフサイクルは
未実施/量産検証/実生産の StatusChip。実生産=ok・量産検証=warn系・未実施=neutral）。

### 6.5 エッジPC
登録フォーム（Panel）＋一覧テーブル（接続状態ドット・接続テスト/有効化/削除）。

> **実装時の変更（タスク9）**:
> - 一覧の表示を既存のカードグリッドからテーブルへ変更した（§6.5 が「一覧テーブル」と
>   明記しているため、記載に忠実に合わせた。既存の登録・接続テスト・有効化/無効化・
>   削除の操作ロジックは無変更）。
> - 削除ボタンは破壊的操作のため `Button variant="danger"` を採用（§6.5 にボタン種別の
>   指定はなく実装時に決定）。

## 7. チャート共通仕様（recharts テーマユーティリティを1つ新設）

`frontend/src/styles/chartTheme.ts`（定数のエクスポート）に集約:

- グリッド線 `--chart-grid`・軸/目盛文字 11px `--color-text-secondary`
- 線幅2px・最終点マーカー（白縁3.5px）・棒は藍単色＋上角丸2px
- 閾値線 = 破線 `6 4`。**対応する系列と同色**
  （NG率チャートのみ系列が1本なので閾値は赤 `--chart-threshold`）
- ツールチップ: 生成りカード様式（surface＋border＋radius のインラインスタイル）
- `connectNulls={false}` 維持（欠損日は線を切る）
- 凡例は2系列以上のチャートのみ表示。値ラベルの常時表示はしない

> **実装時の変更（タスク4）**: 閾値線は `ReferenceLine`（定数y値）ではなく既存の
> `Line type="stepAfter"` を維持した。閾値は色別／期間別に有効期間を持ち日次で
> 変化・欠損しうる（dashboard spec R3・`resolve_effective`）ため、`ReferenceLine`
> では表現できない。見た目（破線6 4・対応系列と同色）のみ本節に合わせた。
> また `chartTheme.ts` の色定数は `tokens.css` の値を**リテラルhexで複製**する
> （recharts は stroke/fill をSVGプレゼンテーション属性として設定するため、
> Chromium系ブラウザで `var(--x)` が解決されない）。`contentStyle` 等の
> インラインstyle経由の値は `var()` のままでよい。

## 8. 実装制約

- **変更しない**: `frontend/src/api/`・`hooks/`・ルーティング・バックエンド全体
- 表示要素の追加（スパークライン・残りpt等）は既存レスポンスからの導出のみ。
  導出できない場合はその要素を落とす（APIを増やさない）
- 既存テストの意図を変えない。class名・文言変更で壊れるテストは表示仕様の変更として追随修正
- コミットは共通基盤（tokens/ui部品/シェル）→ ページ単位で分割
