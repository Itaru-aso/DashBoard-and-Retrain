# color 彩度/色味ドリフト対応（566番新設備・ST側augmentation拡張検証＋データ再学習） v1.5

> 位置づけ: `retraining` spec の `design.md` を上書きせず、566番新設備立ち上げに伴う color の
> 彩度/色味ドリフト対応に関する意思決定記録（ADR）として独立管理する。
> augmentation拡張部分は CLAUDE.md「学習ロジック変更不可」への**追加承認済み例外**
> （2026-08-21 ユーザー承認、design-decisionスキルによる設計判断）。
> データ再学習部分は CLAUDE.md の制約対象外（データ追加は既存運用の範囲、例外化不要）。

## 目的 / 背景

566番の新設備立ち上げに伴うドメインシフト診断（`inspection-domain-shift-diagnosis` skill使用）で、
colorモデルに輝度・シャープネスでは説明できない残存の異常スコア上昇が見つかった。現場調整
（照度・ピント）を5ラウンド実施し輝度・シャープネスは学習データに接近したが、スコア平均は
学習データの約8〜10倍のまま改善しなかった。外れ値2枚（テープ端＋固定ピン写り込み、フレーミング
問題として別途対応済み）を除いた残存原因を調査した結果、**HSV彩度が-15%（117.5→100.4）、
R-B色味差が-26%（15.8→11.6）** とズレていることを確認した（詳細は引き継ぎ資料
`.claude/handoff/color-augmentation-kickoff.md` 参照）。

### 設計判断の前提（2026-08-21 ユーザー確認）

- **号機展開予定**: あり（台数未定）。567 monochro ADR と同様、augmentationの「将来ドリフトへの
  保険」としての価値が成立する前提がある。
- **物理調整（ホワイトバランス/色温度）の余地**: **実質上限**。これ以上の現場調整では
  彩度ズレを埋められない（567の物理調整には伸ばせる余地があったのに対し、本件は条件が異なる）。
- **運用インパクト**: 虚報が業務に支障、即対応が必要（緊急度高）。
- **検証実験の可否**: 567 monochro ADR と同等の系統的探索（数日規模）を回せる。
- **ゲート(b)の意味（2026-08-21 ユーザー確認・重要）**: 「既存の設備で撮像した学習データを用いて
  撮像したデータと同様の精度で推論が可能なこと」は、**既存設備データのみで学習したモデル
  （＝新設備データを学習に加えていないモデル）の一般化能力**を測るものであり、
  新設備データを追加して再学習したモデルの精度確認ではない。したがって本ADRの検証の主眼は
  **augmentation拡張による一般化改善**であり、後述のデータ再学習（決定3）は別レーンの
  緊急対応であって本ADRのゲート(a)(b)の直接の評価対象ではない。

## 技術的前提（コード調査で確認済みの事実）

- `training/conf/config.yaml` の `color:` セクション（187行目〜）は**color_no非依存**の
  単一ブロックであり、全color番号の学習に共通適用される。`color-anomaly-score-cand1-pilot.md`
  の cand1（`para.json` の `cand1_enabled` で color_no ごとに opt-in）とは異なり、
  augmentation設定には color_no 単位のパイロット機構が存在しない。したがって augmentation
  拡張を採用する場合、566以外の色番への影響も検証対象になる。
- 現行の color 側 augmentation（`st_augmentation`: brightness/contrast/saturation 各0.1、
  `penalty_augmentation`: brightness/contrast/saturation 各0.2 + grayscale 0.3 +
  random_erasing 0.1、AE分岐: saturation 0.2 等）は、`color-anomaly-score-cand1-pilot.md`
  決定18（2026-07-30、color_no=316）で**弱める方向を4パターン全て実測済み**
  （random_erasing・grayscale・color_jitter・AE noise/blur、いずれも同一FPR水準で
  検知率-2.6〜7.8pt悪化）。**強める方向・新規追加（hue）方向は未検証**。
- `training/train/common.py:get_st_transform()` の ColorJitter 呼び出しは
  `brightness/contrast/saturation` のみで **hue は配線されていない**（`0` 固定）。
  hue jitter の追加は関数への新規引数追加＝コード変更に該当する。
  **彩度jitterは色相を回転させない**ため、ホワイトバランス/色温度差に由来する色味シフト
  （R-B -26%、これは色相方向の変化）には彩度jitterだけでは原理的に対応できない可能性が高い
  （567 monochro ADR が「blurのみ」を最初の候補から外した理由――シャープネス方向のズレに
  対しては鮮明化(sharpen)側でなければ目的に合致しない――と同型の、メカニズム不一致の懸念）。
- 566 color の欠陥データ規模: `4_dataset/566/color` で defect train 58枚 + test 26枚 = 84枚。
  001（43枚）・316（123枚）の既存ADRで使われた規模と同水準だが、**感度検証（ホールドアウト）
  として使えるのは test の26枚のみ**（train 58枚は学習の教師信号として使われるため、
  channel_weights等を通じて in-sample になる）。001・316のADRで確認済みの通り、
  **cross-color評価（他色番のモデルで採点）は感度を過大評価する**ため、gate(a)の感度確認は
  各色番自身のモデルで行う。

## 決定事項

1. **本ADRの主眼＝color ST側augmentationの拡張検証**（既存設備データのみで学習したモデルの
   新設備画像への一般化能力を、augmentationでどこまで改善できるかを検証する）。
   観測されたズレは彩度（スケール方向、-15%）と色味（色相方向、-26%）の2軸であり、
   メカニズムが異なるため、**単一要因のまま2本の候補を並行して検証**する
   （直列に「彩度がダメならhue」とはしない。彩度jitterは色相を回転させず、色味ズレの
   メカニズムには対応できないため）。
   - **候補A**: 既存パラメータ `st_augmentation.color_jitter_saturation`（現行0.1）の強化のみ
     （具体値は探索実験で決定）。**コード変更不要（config値変更のみ）**。彩度スケールのズレに対応。
   - **候補B**: hue jitter の新規追加（`get_st_transform` へのコード変更、config-gated・
     既定無効）。色味（色相方向）のズレに対応。
   - いずれも567 monochro ADR と同じ方法論（最小有効量の原則・単一要因検証・短縮学習での
     スクリーニング→フル長で確定・感度非劣化ゲート）で実施する。候補A・Bを最初から
     組み合わせた構成は検証しない（567・316の教訓「同時投入は負の相互作用」を踏まえ、
     まず単独効果を確認する）。
2. **検証ゲート**（2026-08-21 ユーザー確定・本項で解釈を明確化）:
   - **(a) 非劣化ゲート**: 566に加えて代表色番（001・316等、過去ADRで使用実績があり
     比較可能）で、**各色番は自身のモデルで採点**し、既存モデル対比で検知率・分離マージンが
     悪化しないこと（cross-color評価は使用しない）。
   - **(b) 新設備一般化ゲート**（2026-08-21 データ内容確定・下記に更新）: **既存設備データ
     のみで学習した**候補モデル（augmentation変更のみを加え、新設備データは学習に含めない）
     で、新設備実測画像（`\\digi2\止水F色物画像検査\画像データ\撮像テスト\566\color`、
     全14枚が新設備で撮像した良品画像とユーザー確定。命名`NG_image_*`は撮像テスト時に
     虚報として捕捉されたことの記録であり、実際は良品）を推論し、この14枚が正しくOK判定
     に転じること（虚報の解消）を確認する。
     - この14枚は**新設備良品の母集団からのランダム抽出ではなく、既に虚報として捕捉された
       既知の問題ケース**である。したがって本ゲートは「既知の虚報14件が解消するか」の
       before/after比較であり、新設備全体の一般的なFP率の推定ではない
       （一般的FP率の推定が別途必要な場合は「未実施・今後の課題」参照）。
     - 新設備での検知率（見逃し方向）は本ゲートでは検証できない（good画像のみのため）。
       567の P環境検証（val good 348枚・defect 1枚のみで新ドメイン感度は「検証不可能」と
       明記）と同種の残存リスクとして記録する。
     - 103455〜103459の約4秒間の連続撮像であり、567の val/good（80秒348枚でもフレーム間
       独立性が問題視された）と同様に実質的な独立標本数はさらに少ない可能性がある。
       n=14では時間ブロック分割は実施できないため、個々の画像単位でのスコア変化を確認する。
3. **緊急対応（別レーン・即着手可・gate(a)(b)の直接の評価対象外）**: 566の新設備実測データ
   （良品中心、可能なら不良も）を追加収集し、既存の枠内で566 colorモデルを再学習する。
   - このモデルは「既存設備データのみで学習」という gate(b) の前提から外れるため、
     gate(b) の合否判定には使わない。567 monochro ADR で実証済みの効果
     （augmentation単独ではFP 32.5%止まり、新設備データ追加で0.0%まで改善）に基づく、
     業務支障の即時緩和を目的とした対応であり、決定1・2（augmentation検証）とは独立に進める。
   - 再学習モデル自身の効果を確認する場合も、新設備検証画像を学習・channel_weights算出の
     どちらにも使わない held-out split を明示すること（567で新設備NG 23枚中15枚が
     channel_weights算出にin-sampleだったため、学習未使用8枚のみで確認したという前例に倣う）。
   - CLAUDE.md「学習ロジック不可侵」の対象外（データ追加のみ、モデル構造・損失関数・
     学習ループへの変更を伴わない）。**ADR承認不要、即着手可**。
4. **スコープの注意（cand1パイロットとの違い）**: color の augmentation 設定は color_no
   非依存（技術的前提の節参照）。566限定のパイロット化はできないため、gate(a)は566に加えて
   代表色番でも確認し、他色番への悪影響がないことを確認してから config.yaml へ恒久化する。
5. **実施順序**: 決定3（データ再学習）は緊急対応として並行して即着手する。決定1・2
   （augmentation拡張の検証）は本ADRの主眼として系統的に実施する。両者は独立レーンだが、
   567・316で確認された「2つの変更の同時投入は負の相互作用を起こし得る」教訓に従い、
   将来的に両方を本番へ統合する場合は個別効果を切り分けて確認してから組み合わせる。

## 却下した代替案

- **彩度jitter強化のみを先に試し、不十分な場合にのみhue追加する直列ゲート（当初案）**:
  彩度jitterは色相を回転させないため、観測されたR-B色味ズレ（色相方向、-26%）のメカニズムに
  単独では対応できない可能性が高い。567の「blurのみ」候補が却下された理由（観測されたズレの
  方向と候補の効果方向が一致しない）と同型のため、直列ではなく候補A・Bの並行検証に変更した
  （2026-08-21、advisorレビューを受けて修正）。
- **物理調整のみで完結**: ユーザー確認により現場調整は実質上限に達しており、これ以上の
  現場調整では彩度ズレを吸収できない（前提の節参照）。不採用。
- **augmentation拡張の検証が終わるまでデータ再学習を待つ**: 567の実測（augmentation単独では
  FP 32.5%止まり、新設備データ追加で0.0%）に基づくと、augmentationだけでは業務支障
  （虚報による検査業務の滞り）を即時解消できる見込みが低い。緊急度に対して系統的探索
  （数日規模）は間に合わない可能性があるため、データ再学習（決定3）を待たずに並行の
  緊急対応レーンとして即時実施する。
- **既存augmentation強度を弱める方向の再検証**: `color-anomaly-score-cand1-pilot.md` 決定18で
  4パターンとも悪化が既に確認済み（2026-07-30、色番316）であり、再検証の必要性は低い。
  本ADRは「強める・新設」方向のみを対象とする。

## 制約 / 非目標

- 損失関数・モデル構造・学習ループ本体は変更しない（変更は `get_st_transform` への
  hue jitter追加（候補B）と `config.yaml` の値変更（候補A）に限る）。
- brightness/contrast の拡張は対象外（決定18で悪化が確認済みのため再検証しない）。
- 566以外の号機の個別ドリフト傾向の事前診断は本ADRの範囲外（保険策が実際に効くかは
  各号機立ち上げ時に個別に確認する）。
- 決定3（データ再学習）の実施内容そのもの（何枚収集するか等の運用詳細）は本ADRのスコープ外。
  本ADRでは「gate(a)(b)の対象外である」という位置づけのみを規定する。

## 検証基準（ゲート）

- 単体テスト: `get_st_transform` の新規パラメータ（候補Aの既存キー値変更、候補Bのhueキー追加）
  のgating（既定=現行値/無効で従来と同一変換列、変更時のみ適用）が green。
- ゲート(a) 非劣化: 566 + 代表色番（001・316等）で、**各色番自身のモデル**で採点した
  検知率・分離マージンが既存モデル対比で悪化しないこと。
- ゲート(b) 新設備一般化: **既存設備データのみで学習した**候補モデルで、新設備実測の良品14枚
  （`\\digi2\止水F色物画像検査\画像データ\撮像テスト\566\color`、既知の虚報ケース）を推論し、
  すべて（または大部分）が正しくOK判定に転じること。n=14・単一バーストのため統計的な
  一般化はできず、この14件のbefore/after比較として扱う。

## 実験計画（Phase A〜C・567同型、v1.2追記）

> 本節は実験の**設計のみ**を記録する。実際の学習ジョブ起動（GPU・数時間〜数日規模）は
> このADRの範囲外であり、実行はユーザーの承認・スケジューリングに委ねる。

### Phase A: ベースライン測定

- 対象色番: 566（本題）+ 001・316（代表色番、gate(a)の比較可能性のため）。
- 現行モデル（st_augmentation変更なし）で、**各色番自身のモデル**で採点:
  - gate(a)基礎値: test held-outでの検知率・分離マージン（566=test26枚、316=test115枚等）。
  - gate(b)基礎値: 566の新設備良品14枚（既知の虚報ケース）を現行モデルで推論し、
    現状の虚報件数・スコアを記録する（対策前の基準点として必須）。
- 目的: 「対策後にどれだけ改善したか」の基準点を確定する。時間が許せば567のA2/A3と同様に
  別seedでの再学習を1回追加し、ノイズフロアを把握する（任意）。

### Phase A実測結果（2026-08-21、ユーザー指示により対象色番を566・030・841・316に拡大）

`training/_scratch_566_saturation_drift/phase_a_baseline.py`（16スレッド並列・良品は
色番ごと最大500枚をseed=42でランダムサンプル、不良品は全数）で、各色番の現行モデル(ONNX)を
`export_root/019ef71b-.../binary/<color_no>/{good_uuid,defect_uuid}`（既にcrop/rotate/
top-bottom分割済み、resizeのみで推論可）に対して実推論した。生スコアは
`phase_a_baseline_results.json`に保存。

**重要な訂正**: 当初 ONNX メタデータの `threshold`（学習時のnative較正値、決定11で指摘した
尺度不整合を持つ値）で判定したところ、全色番で false_alarm_rate=0.0000 なのに
miss_rate=89〜98%という不自然な結果になった。**ユーザー確認により、この算出閾値は
既知の問題があるため実運用では使用せず、全色番とも人手でマニュアル設定した閾値1.2で
運用している**ことが判明。以下は threshold=1.2 で再計算した結果（画像の再読み込みは不要、
保存済みスコアから再計算）。

| 色番 | n_good(サンプル)/n_defect(全数) | 虚報率(FP) | 見逃し率(miss_rate) | F1 |
|---|---|---|---|---|
| 566 | 500/39 | 0.0% | 38.5% | 0.762 |
| 030 | 500/103 | 1.6% | 42.7% | 0.694 |
| 841 | 500/376 | 0.0% | 86.4% | 0.239 |
| 316 | 500/427 | 0.2% | 51.5% | 0.652 |

**gate(b)基礎値（566新設備良品14枚、既知の虚報ケース、threshold=1.2）**: **14枚全てが
虚報（score 1.90〜3.25、いずれも1.2超）**。診断結果（新設備の良品がリアルタイム判定で
虚報になる）と完全に整合する。これが対策前の基準点であり、Phase B/Cで検証する候補は
「この14枚のうち何枚がOK判定に転じるか」で改善を測る。

**threshold=1.0での参考値**（同一の保存済みスコアから再計算、画像再読み込みなし）:

| 色番 | 虚報率(FP) | 見逃し率(miss_rate) | F1 |
|---|---|---|---|
| 566 | 0.2% | 33.3% | 0.788 |
| 030 | 3.4% | 35.9% | 0.710 |
| 841 | 0.0% | 85.1% | 0.259 |
| 316 | 0.2% | 44.5% | 0.713 |

566の新設備良品14枚は threshold=1.0 でも全14枚が虚報のまま（最小スコア1.9049のため、
この14枚をOK判定に転じさせるには threshold を1.9超まで上げる必要がある）。
1.0は1.2より全色番で虚報率がわずかに上がり見逃し率が下がる方向（F1はやや改善）。

**841モデルの再評価（2026-08-21、ユーザー指示）**: `training/6_model/841/color/`にONNXが
存在しないため当初 `D:\0032011\生産検証\model\841_color_model.onnx`（実運用モデル扱い）を
使用したが、`training/6_model_exp_epochs65_step45000/841/color/841_color_model.onnx`
（`_scratch_841_experiment`の比較検証構成の一つ）でも同一サンプル（良品500枚・不良376枚）で
再評価した。

| 841モデル | AUC | miss_rate@threshold=1.2 | miss_rate@threshold=1.0 |
|---|---|---|---|
| 生産検証/model（前回使用） | 0.826 | 86.4% | 85.1% |
| `6_model_exp_epochs65_step45000` | **0.933** | **74.5%** | **67.0%** |

epochs65_step45000モデルの方が明確に優れる（AUC+0.107、見逃し率10〜18pt改善）が、
他色番（566: 33〜38%、030: 36〜43%、316: 44〜52%）と比べると依然突出して高い。

**残る注意点**:
- 841は見逃し率が他色番より著しく高い（どちらのモデルでも67〜86%）。566の彩度/色味ドリフト
  とは別の要因（モデル自体が発展途上、`training/_scratch_841_experiment/`で複数構成を
  比較検証中）である可能性が高く、本ADRのスコープ（566の彩度/色味ドリフト対応）の外の
  問題として扱う。841側の改善はスコープ外の別タスクとして扱い、本ADRの候補A/B検証では
  841を代表色番として深追いしない。
- 良品はサンプリング（各色番最大500枚/全3300〜4000枚超）のため、全数評価ではない
  （ネットワークI/O時間の制約による判断。この14枚のような少数の既知ケースでの
  before/afterと異なり、母集団推定としての精度は500サンプル分の統計的揺れを含む）。
- ONNXメタデータの`threshold`（native較正値）は実運用で使われていないことが確認されたため、
  今後この色番群の評価では**threshold=1.2を基準値として使う**（own_thresholdは参考値扱い）。

### Phase B: 単一要因スクリーニング（短縮学習）

- **候補A（彩度jitter強化）**: `st_augmentation.color_jitter_saturation` を 0.1→0.15、
  0.1→0.2 の2段階で試す（567のsharpen_factor探索と同様、控えめな値から開始）。
  コード変更不要、config値変更のみ。
- **候補B（hue jitter新規追加）**: `get_st_transform` にhue対応を追加する
  （config-gated・既定無効、`torchvision.transforms.ColorJitter`のhue引数を使用）。
  値は小さめから開始（例: hue=0.02, 0.05。ColorJitterのhue範囲[-0.5, 0.5]でhue=0.05は
  約±18度相当）。
- 学習は短縮（567同様、max_train_step等を縮小した高速スクリーニング）。対象は566のみで良い
  （スクリーニング段階）。
- 判定: gate(b)の14枚での改善度（スコア低下・OK判定への転換数）と、566 test26枚での
  検知率・分離マージンの変化を見る。
- 567・decision16の教訓「短縮学習は構成間の順位を保存しない」を踏まえ、Phase Bは
  有効性の有無の大まかなスクリーニングに限定し、優劣の確定はPhase Cのフル長で行う。

### Phase C: フル長確定

- Phase Bで有効性が確認された候補（A・B単独。組み合わせは567・316の「同時投入は負の相互作用」
  の教訓により、両方が有効だった場合のみ追加で確認する）をフル長（epochs=50、decision19の
  既存標準）で再学習する。
- 566に加えて001・316でも同一構成でgate(a)を確認する（各色番自身のモデルで採点）。
- gate(a)(b)両方を満たした構成を、config.yaml への恒久化候補として確定する。

## 未実施・今後の課題

- **gate(b)用の新設備良品データ（2026-08-21確認・ユーザー確定）**:
  `\\digi2\止水F色物画像検査\画像データ\撮像テスト\566\color` の14枚は、**すべて新設備で
  撮像した良品画像**であることをユーザーが確定した。ファイル名が `NG_image_*` なのは、
  この診断の核心そのもの（新設備の良品がリアルタイム判定でNGと誤判定される＝虚報）を
  反映したものであり、フォルダ内に不良品は含まれない。
  - **位置づけの注意**: この14枚は撮像テスト時に**既に虚報として捕捉された既知の問題ケース**
    であり、新設備の良品母集団からのランダム抽出ではない。したがって「新設備全体の虚報率」を
    推定する用途には使えないが、「この14枚が対策後に正しくOK判定されるか」という
    **before/after の直接比較**には使える（567 monochro ADR の 181実NG 10枚・
    P環境defect n=1 と同種の、少数の既知ケースでの非劣化/改善確認と同じ位置づけ）。
  - **統計的注意**: 103455〜103459の約4秒間の連続撮像であり、567のval/good（80秒348枚でも
    フレーム間独立性が問題視された）と同様に、この14枚は実質的な独立標本数がさらに少ない
    可能性がある。時間ブロック分割は本データの規模では実施できないため、n=14を1つの
    確認セットとして扱い、個々の画像のスコア変化（虚報→正常判定に転じたか）を確認する
    形の検証とする。
  - **残る課題**: 一般的な新設備FP率（ランダムサンプルでの虚報率）の推定には、この14枚とは
    別に、新設備での通常運転時の良品画像（虚報ではなかったものも含む母集団）のサンプリングが
    別途望ましい。決定3（データ再学習）の収集作業と同じ撮像機会を使い回せる可能性が高いが、
    gate(b)用には**再学習に使わないhold-out分を確保する**必要がある。
  - ご提示の `export_root/019ef71b-.../binary/566/` 配下2フォルダ（良品3840枚/不良品39枚）は
    **566の既存（学習済み）データであり新設備ドリフトを反映していない**とユーザー確認済み
    （全ファイル2026-07-28タイムスタンプ）。既存設備側の参照精度（gate(b)の比較先）としては
    使えるが、新設備側のデータにはならない。
- augmentation拡張検証（候補A・B）の実験計画は設計済み（上記「実験計画」節）。**実行
  （Phase A〜Cの学習ジョブ起動）はユーザーの承認・スケジューリング待ち**。
- 他号機展開時のドリフト傾向の事前把握（本保険策が実際に効くかは継続検証が必要）。
