# color 彩度/色味ドリフト対応（566番新設備・ST側augmentation拡張検証＋データ再学習） v1.1

> 位置づけ: `retraining` spec の `design.md` を上書きせず、566番新設備立ち上げに伴う color の
> 彩度/色味ドリフト対応に関する意思決定記録（ADR）として独立管理する。
> augmentation拡張部分は CLAUDE.md「学習ロジック変更不可」への**追加承認済み例外**
> （2026-08-21 ユーザー承認、design-decisionスキルによる設計判断）。
> データ再学習部分は CLAUDE.md の制約対象外（データ追加は既存運用の範囲、例外化不要）。

## 目的 / 背景

566番の新設備立ち上げに伴うドメインシフト診断（`inspection-domain-shift-diagnosis` skill使用）で、
colorモデルに輝度・シャープネスでは説明できない残存の異常スコア上昇が見つかった。現場調整
（照度・ピント）を5ラウンド実施し輝度・シャープネスは学習データに接近したが、スコア平均は
学習データの約8〜10倍のまま改善しなかった。外れ値2枚（テープ端＋固定ピン写り込み、フレーミング
問題として別途対応済み）を除いた残存原因を調査した結果、**HSV彩度が-15%（117.5→100.4）、
R-B色味差が-26%（15.8→11.6）** とズレていることを確認した（詳細は引き継ぎ資料
`.claude/handoff/color-augmentation-kickoff.md` 参照）。

### 設計判断の前提（2026-08-21 ユーザー確認）

- **号機展開予定**: あり（台数未定）。567 monochro ADR と同様、augmentationの「将来ドリフトへの
  保険」としての価値が成立する前提がある。
- **物理調整（ホワイトバランス/色温度）の余地**: **実質上限**。これ以上の現場調整では
  彩度ズレを埋められない（567の物理調整には伸ばせる余地があったのに対し、本件は条件が異なる）。
- **運用インパクト**: 虚報が業務に支障、即対応が必要（緊急度高）。
- **検証実験の可否**: 567 monochro ADR と同等の系統的探索（数日規模）を回せる。
- **ゲート(b)の意味（2026-08-21 ユーザー確認・重要）**: 「既存の設備で撮像した学習データを用いて
  撮像したデータと同様の精度で推論が可能なこと」は、**既存設備データのみで学習したモデル
  （＝新設備データを学習に加えていないモデル）の一般化能力**を測るものであり、
  新設備データを追加して再学習したモデルの精度確認ではない。したがって本ADRの検証の主眼は
  **augmentation拡張による一般化改善**であり、後述のデータ再学習（決定3）は別レーンの
  緊急対応であって本ADRのゲート(a)(b)の直接の評価対象ではない。

## 技術的前提（コード調査で確認済みの事実）

- `training/conf/config.yaml` の `color:` セクション（187行目〜）は**color_no非依存**の
  単一ブロックであり、全color番号の学習に共通適用される。`color-anomaly-score-cand1-pilot.md`
  の cand1（`para.json` の `cand1_enabled` で color_no ごとに opt-in）とは異なり、
  augmentation設定には color_no 単位のパイロット機構が存在しない。したがって augmentation
  拡張を採用する場合、566以外の色番への影響も検証対象になる。
- 現行の color 側 augmentation（`st_augmentation`: brightness/contrast/saturation 各0.1、
  `penalty_augmentation`: brightness/contrast/saturation 各0.2 + grayscale 0.3 +
  random_erasing 0.1、AE分岐: saturation 0.2 等）は、`color-anomaly-score-cand1-pilot.md`
  決定18（2026-07-30、color_no=316）で**弱める方向を4パターン全て実測済み**
  （random_erasing・grayscale・color_jitter・AE noise/blur、いずれも同一FPR水準で
  検知率-2.6〜7.8pt悪化）。**強める方向・新規追加（hue）方向は未検証**。
- `training/train/common.py:get_st_transform()` の ColorJitter 呼び出しは
  `brightness/contrast/saturation` のみで **hue は配線されていない**（`0` 固定）。
  hue jitter の追加は関数への新規引数追加＝コード変更に該当する。
  **彩度jitterは色相を回転させない**ため、ホワイトバランス/色温度差に由来する色味シフト
  （R-B -26%、これは色相方向の変化）には彩度jitterだけでは原理的に対応できない可能性が高い
  （567 monochro ADR が「blurのみ」を最初の候補から外した理由――シャープネス方向のズレに
  対しては鮮明化(sharpen)側でなければ目的に合致しない――と同型の、メカニズム不一致の懸念）。
- 566 color の欠陥データ規模: `4_dataset/566/color` で defect train 58枚 + test 26枚 = 84枚。
  001（43枚）・316（123枚）の既存ADRで使われた規模と同水準だが、**感度検証（ホールドアウト）
  として使えるのは test の26枚のみ**（train 58枚は学習の教師信号として使われるため、
  channel_weights等を通じて in-sample になる）。001・316のADRで確認済みの通り、
  **cross-color評価（他色番のモデルで採点）は感度を過大評価する**ため、gate(a)の感度確認は
  各色番自身のモデルで行う。

## 決定事項

1. **本ADRの主眼＝color ST側augmentationの拡張検証**（既存設備データのみで学習したモデルの
   新設備画像への一般化能力を、augmentationでどこまで改善できるかを検証する）。
   観測されたズレは彩度（スケール方向、-15%）と色味（色相方向、-26%）の2軸であり、
   メカニズムが異なるため、**単一要因のまま2本の候補を並行して検証**する
   （直列に「彩度がダメならhue」とはしない。彩度jitterは色相を回転させず、色味ズレの
   メカニズムには対応できないため）。
   - **候補A**: 既存パラメータ `st_augmentation.color_jitter_saturation`（現行0.1）の強化のみ
     （具体値は探索実験で決定）。**コード変更不要（config値変更のみ）**。彩度スケールのズレに対応。
   - **候補B**: hue jitter の新規追加（`get_st_transform` へのコード変更、config-gated・
     既定無効）。色味（色相方向）のズレに対応。
   - いずれも567 monochro ADR と同じ方法論（最小有効量の原則・単一要因検証・短縮学習での
     スクリーニング→フル長で確定・感度非劣化ゲート）で実施する。候補A・Bを最初から
     組み合わせた構成は検証しない（567・316の教訓「同時投入は負の相互作用」を踏まえ、
     まず単独効果を確認する）。
2. **検証ゲート**（2026-08-21 ユーザー確定・本項で解釈を明確化）:
   - **(a) 非劣化ゲート**: 566に加えて代表色番（001・316等、過去ADRで使用実績があり
     比較可能）で、**各色番は自身のモデルで採点**し、既存モデル対比で検知率・分離マージンが
     悪化しないこと（cross-color評価は使用しない）。
   - **(b) 新設備一般化ゲート**: **既存設備データのみで学習した**候補モデル
     （augmentation変更のみを加え、新設備データは学習に含めない）で、新設備実測画像
     （`\\digi2\止水F色物画像検査\画像データ\撮像テスト\566\color`）を推論し、既存設備
     データでの精度と同水準まで改善すること。実施前に以下を確認する:
     - 当該フォルダに defect が含まれるか。good のみであれば FP（虚報）方向のみの確認となり、
       新設備での検知率（見逃し方向）は本ゲートでは検証できない――567の P環境検証
       （val good 348枚・defect 1枚のみで新ドメイン感度は「検証不可能」と明記）と同種の
       残存リスクとして記録する。
     - 当該フォルダの画像が短時間の連続撮像バーストである場合、567の val/good
       （80秒間348枚・隣接フレームがほぼ同一）と同様にフレーム間の独立性がないため、
       ランダム分割ではなく時間ブロック分割（前半=構成選抜用、後半=最終確認用）を用いる。
3. **緊急対応（別レーン・即着手可・gate(a)(b)の直接の評価対象外）**: 566の新設備実測データ
   （良品中心、可能なら不良も）を追加収集し、既存の枠内で566 colorモデルを再学習する。
   - このモデルは「既存設備データのみで学習」という gate(b) の前提から外れるため、
     gate(b) の合否判定には使わない。567 monochro ADR で実証済みの効果
     （augmentation単独ではFP 32.5%止まり、新設備データ追加で0.0%まで改善）に基づく、
     業務支障の即時緩和を目的とした対応であり、決定1・2（augmentation検証）とは独立に進める。
   - 再学習モデル自身の効果を確認する場合も、新設備検証画像を学習・channel_weights算出の
     どちらにも使わない held-out split を明示すること（567で新設備NG 23枚中15枚が
     channel_weights算出にin-sampleだったため、学習未使用8枚のみで確認したという前例に倣う）。
   - CLAUDE.md「学習ロジック不可侵」の対象外（データ追加のみ、モデル構造・損失関数・
     学習ループへの変更を伴わない）。**ADR承認不要、即着手可**。
4. **スコープの注意（cand1パイロットとの違い）**: color の augmentation 設定は color_no
   非依存（技術的前提の節参照）。566限定のパイロット化はできないため、gate(a)は566に加えて
   代表色番でも確認し、他色番への悪影響がないことを確認してから config.yaml へ恒久化する。
5. **実施順序**: 決定3（データ再学習）は緊急対応として並行して即着手する。決定1・2
   （augmentation拡張の検証）は本ADRの主眼として系統的に実施する。両者は独立レーンだが、
   567・316で確認された「2つの変更の同時投入は負の相互作用を起こし得る」教訓に従い、
   将来的に両方を本番へ統合する場合は個別効果を切り分けて確認してから組み合わせる。

## 却下した代替案

- **彩度jitter強化のみを先に試し、不十分な場合にのみhue追加する直列ゲート（当初案）**:
  彩度jitterは色相を回転させないため、観測されたR-B色味ズレ（色相方向、-26%）のメカニズムに
  単独では対応できない可能性が高い。567の「blurのみ」候補が却下された理由（観測されたズレの
  方向と候補の効果方向が一致しない）と同型のため、直列ではなく候補A・Bの並行検証に変更した
  （2026-08-21、advisorレビューを受けて修正）。
- **物理調整のみで完結**: ユーザー確認により現場調整は実質上限に達しており、これ以上の
  現場調整では彩度ズレを吸収できない（前提の節参照）。不採用。
- **augmentation拡張の検証が終わるまでデータ再学習を待つ**: 567の実測（augmentation単独では
  FP 32.5%止まり、新設備データ追加で0.0%）に基づくと、augmentationだけでは業務支障
  （虚報による検査業務の滞り）を即時解消できる見込みが低い。緊急度に対して系統的探索
  （数日規模）は間に合わない可能性があるため、データ再学習（決定3）を待たずに並行の
  緊急対応レーンとして即時実施する。
- **既存augmentation強度を弱める方向の再検証**: `color-anomaly-score-cand1-pilot.md` 決定18で
  4パターンとも悪化が既に確認済み（2026-07-30、色番316）であり、再検証の必要性は低い。
  本ADRは「強める・新設」方向のみを対象とする。

## 制約 / 非目標

- 損失関数・モデル構造・学習ループ本体は変更しない（変更は `get_st_transform` への
  hue jitter追加（候補B）と `config.yaml` の値変更（候補A）に限る）。
- brightness/contrast の拡張は対象外（決定18で悪化が確認済みのため再検証しない）。
- 566以外の号機の個別ドリフト傾向の事前診断は本ADRの範囲外（保険策が実際に効くかは
  各号機立ち上げ時に個別に確認する）。
- 決定3（データ再学習）の実施内容そのもの（何枚収集するか等の運用詳細）は本ADRのスコープ外。
  本ADRでは「gate(a)(b)の対象外である」という位置づけのみを規定する。

## 検証基準（ゲート）

- 単体テスト: `get_st_transform` の新規パラメータ（候補Aの既存キー値変更、候補Bのhueキー追加）
  のgating（既定=現行値/無効で従来と同一変換列、変更時のみ適用）が green。
- ゲート(a) 非劣化: 566 + 代表色番（001・316等）で、**各色番自身のモデル**で採点した
  検知率・分離マージンが既存モデル対比で悪化しないこと。
- ゲート(b) 新設備一般化: **既存設備データのみで学習した**候補モデルによる新設備実測データ
  （`\\digi2\止水F色物画像検査\画像データ\撮像テスト\566\color`）の推論精度が、既存設備データ
  での精度と同水準まで改善すること。実施前に該当フォルダのdefect有無・撮像条件（連続バースト
  か）を確認し、バーストであれば時間ブロック分割を用いる。

## 未実施・今後の課題

- `\\digi2\止水F色物画像検査\画像データ\撮像テスト\566\color` のdefect有無・撮像条件
  （連続バーストかどうか、枚数）の確認（gate(b)実施の前提）。
- 566の新設備良品/不良データの実際の収集状況・枚数の確認（決定3の着手前提）。
- augmentation拡張検証（候補A・B）の具体的な実験計画（567同型のPhase A〜C）の設計・実施。
- 他号機展開時のドリフト傾向の事前把握（本保険策が実際に効くかは継続検証が必要）。
