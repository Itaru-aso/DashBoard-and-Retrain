# monochro ST側augmentation拡張（sharpen/blur・撮像環境ドリフト頑強性） v1.0

> 位置づけ: `retraining` spec の `design.md` を上書きせず、学習時augmentationの拡張に関する
> 意思決定記録（ADR）として独立管理する。CLAUDE.md「学習ロジック変更不可」への
> **追加承認済み例外**（2026-08-05 ユーザー承認）。

## 目的 / 背景

2026-08-03 に配信した 567 monochro モデルが実機で全数NG（虚報）となった。分析の結果、
原因は**照明の新品交換＋カメラ・照明の再取り付け**に伴う撮像ドメインシフトであり、
学習データと実機画像の間に以下の差が実測された（分布の重なりなし）:

| 指標 | 学習データ | 実機（交換直後） |
|---|---|---|
| 輝度mean | ≈131（p1≈26, p99≈209） | ≈125（p1≈16, p99≈196） |
| シャープネス（Laplacian分散） | 391〜469（mean≈435） | 202〜368（mean≈308） |

物理調整（照度9段階・ピント16段階の切り分け実験）の結果:
- 照度460が最適（NG率72.7%）だが、以降のピント調整で一度NG率15%（設定E, sharp≈413）を達成後、
  **同一設定に物理的に戻せない**ことが判明（再現性なし）。
- 最終的に再現可能な設定P（sharp≈639、学習データの約1.47倍鮮明）を新標準とする方針を採用。
- 補正実験: per-image mean/std 線形輝度補正では虚報は解消しない（複合的な画質差のため）。

今後の**台数展開・照明経年劣化・保守時の再取り付け**でも同種のドメインシフトが想定されるため、
モデル側に撮像画質（シャープネス方向）の頑強性を持たせる。

### 技術的前提（コード調査で確認済みの事実）

- 異常スコアの主体は **ST（teacher-student）ブランチ**。既存の `pre_tf`（brightness/blur等の
  augmentation）は **AEブランチにのみ**適用され、STブランチには届かない
  （`training/train/common.py` の `TrainTransform.__call__`）。
- STブランチには `st_augmentation`（config-gated）が既に存在するが、
  対応は horizontal_flip / ColorJitter（brightness・contrast・saturation）のみで、
  **シャープネス方向（blur/sharpen）の augmentation は存在しない**。
- 閾値・quantile（q_st）・teacher再正規化・cand1（μ,σ,A,Z）の較正は validation_loader 経由で
  st_tf 適用後の画像に対して行われるため、st_augmentation の拡張は較正側にも自動的に反映される
  （良品スコア分布が広がる → 閾値がその分保守的になる）。

## 決定事項

1. **対象は monochro のみ**。color は現状問題が観測されていないため適用しない。
   `st_augmentation` は mode 別 config セクションのため、monochro セクションにのみ
   新キーを設定することで自然にスコープされる（コード自体は共通だが、既定値は無効）。
2. **追加する変換は sharpen（鮮明化）と blur（ボケ）の両方向**（2026-08-05 ユーザー選択）。
   - sharpen が本命: 新標準P環境（1.47x鮮明）および将来のより鮮明な号機への対応。
   - blur は保険: 照明経年劣化・軽微なピントズレ（今回のボケ側実測 170〜290）への対応。
3. **実装場所**: `training/train/common.py` の `get_st_transform()` に config-gated で追加。
   - sharpen: カスタムクラス `RandomSharpness(factor_min, factor_max, p)` を同ファイルに追加
     （`TF.adjust_sharpness` を factor一様乱数で適用。torchvision 標準の
     `RandomAdjustSharpness` は factor 固定のため連続範囲をカバーできない。
     Windows multiprocessing 対応のため pickle 可能なクラスとして定義し、Lambda は使わない）。
   - blur: torchvision 標準 `RandomApply([GaussianBlur(kernel_size=5, sigma=(0.1, sigma_max))], p)`。
4. **config キー**（`st_augmentation` セクション内・すべて既定で無効=後方互換）:
   | キー | 既定 | monochro設定値 | 根拠 |
   |---|---|---|---|
   | `sharpen_p` | 0（無効） | 0.3 | 無変換の画像も学習に残す |
   | `sharpen_factor_min` | 1.0 | 1.0 | 無変換〜連続的にカバー |
   | `sharpen_factor_max` | 2.0 | 2.0 | 実測較正: factor1.5→1.62x（P=1.47xをカバー）。2.0→2.41xで将来のより鮮明な環境への余裕。感度低下が出た場合の第一縮小候補 |
   | `gaussian_blur_p` | 0（無効） | 0.3 | 同上 |
   | `gaussian_blur_sigma_max` | 0.6 | 0.6 | 実測較正: sigma0.5→0.51x(sharp≈219)。ボケ側観測(170〜290)をカバー |
   - 較正実測（学習ドメイン80half, 2026-08-05）: base mean=429 / sharpen 1.25→1.29x, 1.5→1.62x,
     2.0→2.41x / blur σ0.3→1.00x, σ0.5→0.51x, σ0.8→0.19x。
5. **sharpen と blur は独立の RandomApply**（排他にしない）。同時適用は p²=9% で打ち消し方向に
   働くが、実害は軽微であり、RandomChoice による排他化はコードを複雑にするため採用しない。
6. **検証は2ステップ**（ユーザー指定の計画）:
   - **ステップ1（ドメインシフト対応の効果検証・567）**: 通常データ
     （`export_root`/`export_root_margin` の 567、旧照明ドメイン）で aug 適用の学習を実施。
     従来評価に加え、**P環境実機データ**（`C:\Users\0032011\Downloads\image\567\val`、
     good 348枚/defect 1枚）で新旧モデルのスコア・NG率を比較。
     成功基準: P環境 good の NG率が現行モデル（cand1_T=1.0 で約45〜53%）から有意に低下すること。
   - **ステップ2（不良品感度の非劣化検証・181）**: 181 を aug 適用で再学習し、
     aug適用前モデル（`training/6_model/181/05_CZT8_/monochro`）と不良品感度を比較。
     181 monochro NG 10枚（`export_root` 通常側）で両モデルのスコアを比較し、
     感度（スコアの閾値比・分離度）が低下していないことを確認。良品側FPも併せて比較。
     成功基準: NG画像のスコア/閾値比が旧モデルと同等以上（明確な劣化がない）。
   - 感度低下が観測された場合: `sharpen_factor_max` を 2.0→1.75→1.5 と縮小して再実験
     （blur/sharpen の切り分けが必要な場合は1つずつ無効化して原因特定）。
7. **本ADR確定後の恒久設定**: ステップ1・2 とも合格した場合、monochro の `st_augmentation`
   新キーを config.yaml の標準値として恒久化する。以降の全 monochro 再学習に適用される。

## 却下した代替案

- **blur のみ追加（当初案）**: P環境は学習データより鮮明側のため、blur だけではステップ1の
  検証目的（P環境対応）に合致しない。却下（2026-08-05 ユーザー確認済み）。
- **実機側での輝度・画質後処理補正**: per-image mean/std 線形補正の実験で虚報が解消しないことを
  確認済み。ボケ/鮮明の後処理補正は不確実性が高く不採用。
- **model.py の正規化方式変更（per-image適応正規化）**: モデル構造の変更にあたり
  CLAUDE.md の変更不可領域。ONNX にベイクされる正規化と学習側の不整合リスクも大きい。不採用。
- **AE側 pre_tf の流用・強化**: AEブランチは異常スコアの主体ではなく、ST側に届かないため
  目的に対して無効。不採用。
- **号機ごとの閾値較正のみで対応**: 有効な補完策（設置時に良品N枚で閾値較正）だが、
  モデル自体の頑強性がないと較正しても分離マージンが薄い。augmentation と併用が望ましい
  （閾値較正の標準化は別タスクとして扱う）。

## 制約 / 非目標

- **color 側の学習ロジック・augmentation は変更しない**（config も color セクションは触らない）。
- 損失関数・モデル構造・学習ループ本体は変更しない（変更は `get_st_transform` と
  カスタム変換クラスの追加のみ）。
- 今回級の大シフト（輝度mean 125→160級）を augmentation で吸収することは目標としない。
  それは撮像環境の物理調整＋新ドメインでの再学習が担う。augmentation は±小ドリフトの保険。
- 撮像系ヘルスチェック（保守後の基準統計照合）・号機別閾値較正の運用標準化は別タスク。

## 検証基準（ゲート）

- 単体テスト: `get_st_transform` の新キー gating（既定=無効で従来と同一変換列/有効時に適用）が green。
